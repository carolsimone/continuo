# E2E Test Improvements

**Date:** 2026-04-23
**Branch:** improve-e2e-tests

## Goal

Simplify and clean up the e2e test suite by:
- Moving tests to a cleaner folder structure
- Eliminating the `service-3-broken` Docker image (and its associated `services-fixed` sibling) in favour of embedding failure behaviour directly in SQL
- Reducing the failure test to a minimal, focused 6-node scenario
- Removing the rerun test until a cancel endpoint exists to properly exercise it

## 1. Folder rename: `e2e/` → `tests/e2e/`

Move the entire `e2e/` directory to `tests/e2e/`. The Go module name (`github.com/carolsimone/continuo/e2e`) does not change — only the on-disk path.

Files that reference the old path and must be updated:
- `e2e/go.mod` — `replace` directives use `../orchestrator`, `../state`; these become `../../orchestrator`, `../../state`
- `scripts/setup.sh` — any path like `e2e/` becomes `tests/e2e/`
- `e2e/provision-k8s-test-env.sh`, `deploy-k8s-controllers.sh`, `cleanup-k8s-controllers.sh` — internal script paths
- `e2e/README.md` — all `docker exec` and script invocation examples
- CI workflow files — `docker exec ... go test ... /app/e2e/...` becomes `/app/tests/e2e/...`
- Any `docker-compose.yml` volume mounts that reference `./e2e/`

## 2. Delete `dbt/services/service-3-broken/` and `dbt/services-fixed/`

Both directories are removed entirely. Consequences:

- `scripts/setup.sh`: remove the build step for `service-3-broken` and the `kind load` step for it
- `tests/e2e/provision-k8s-test-env.sh`: same — remove build and load for `service-3-broken`
- No Docker image named `service-3-broken` will be built or loaded into kind anymore

## 3. New failure-tagged models across real services

Six new dbt models are added to the existing service directories. All carry the tag `e2e-schedule-failure` so they appear as a distinct schedule in the UI without interfering with the happy-path schedule (`e2e-schedule`).

The tag is added to each service's `dbt_project.yml` scoped to the `ftable_*` models. Each service's `manifest_v1.json` is regenerated by `setup.sh` at environment bootstrap time — no manual edits to the JSON files.

### DAG shape

```
service-1:  ftable_a (root)  ftable_b (root)
                  \               /
service-3:         ftable_c
                  /         \
service-2:  ftable_d       ftable_e  ← FAILS (joins public.wrong_name)
                  \         /
service-3:         ftable_f          ← never runs
```

### Model SQL

| Path | SQL |
|------|-----|
| `dbt/services/service-1/models/ftable_a.sql` | `SELECT 1 AS id` |
| `dbt/services/service-1/models/ftable_b.sql` | `SELECT 1 AS id` |
| `dbt/services/service-3/models/ftable_c.sql` | `SELECT a.id FROM {{ ref('ftable_a') }} a LEFT JOIN {{ ref('ftable_b') }} b ON a.id = b.id` |
| `dbt/services/service-2/models/ftable_d.sql` | `SELECT id FROM {{ ref('ftable_c') }}` |
| `dbt/services/service-2/models/ftable_e.sql` | `SELECT c.id FROM {{ ref('ftable_c') }} c LEFT JOIN public.wrong_name w ON c.id = w.id` |
| `dbt/services/service-3/models/ftable_f.sql` | `SELECT d.id FROM {{ ref('ftable_d') }} d LEFT JOIN {{ ref('ftable_e') }} e ON d.id = e.id` |

`ftable_e` references `ftable_c` via `{{ ref() }}` so the dbt DAG edge is real, but also joins `public.wrong_name` which does not exist — causing the dbt run to fail at execution time with a relation-not-found error.

### dbt_project.yml changes (per service)

Each service's `dbt_project.yml` gains a new tag entry scoped to `ftable_*` models:

```yaml
# example for service-1
models:
  service_1:
    ftable_a:
      +tags: ["e2e-schedule-failure"]
    ftable_b:
      +tags: ["e2e-schedule-failure"]
```

## 4. Simplify `failure_fixtures.go`

- Replace the current 13-node `getFailureDAG()` (which patched `table_e` to use `service-3-broken`) with a new 6-node version using the `ftable_*` names pointing at their real services.
- Remove `getDiamondDAG()` from this file — it is no longer needed by the failure path.
- Move `getDiamondDAG()` and `getDAGLevels()` to a new `tests/e2e/system_fixtures.go` (they belong to the happy-path test).
- Remove `failureTableServiceMap` and `getFailureServiceNameForTable()` — no longer needed since `service-3-broken` is gone.
- Keep `seedNodes()`, `seedFailureDAG()`, `insertScheduleCatalog()`, and the `failureTest*` constants. Update `failureTestScheduleName` value if it changes (currently `"e2e-schedule-failure"` — keep as-is).

New 6-node DAG definition in `failure_fixtures.go`:

```go
func getFailureDAG() []dagNode {
    return []dagNode{
        {Name: "ftable_a", Dependencies: nil,                          ServiceName: "service-1"},
        {Name: "ftable_b", Dependencies: nil,                          ServiceName: "service-1"},
        {Name: "ftable_c", Dependencies: []string{"ftable_a","ftable_b"}, ServiceName: "service-3"},
        {Name: "ftable_d", Dependencies: []string{"ftable_c"},         ServiceName: "service-2"},
        {Name: "ftable_e", Dependencies: []string{"ftable_c"},         ServiceName: "service-2"},
        {Name: "ftable_f", Dependencies: []string{"ftable_d","ftable_e"}, ServiceName: "service-3"},
    }
}
```

## 5. Simplify `failure_test.go`

Remove the 5-level step-by-step verification (seeds, level-1, level-2, etc.). The test body becomes:

1. `cleanupTestData` for `e2e-schedule-failure`
2. `seedFailureDAG` — seeds 6 nodes directly into Neo4j (bypasses manifest-controller, same as today)
3. `createAndActivateFailureScheduler` — `ActivateSchedule("e2e-schedule-failure")`
4. `verifyNodeExhaustedRetries(t, ctx, clients, schedulerID, "ftable_e")` — wait for 2 retries exhausted
5. `verifyNoJobsDeployed(t, ctx, []string{"ftable_f"})` — downstream never deployed
6. `verifySchedulerFailed(t, ctx, clients, schedulerID)`

The doc-comment is updated to describe the 6-node DAG.

## 6. Generalize `verifyTableEExhaustedRetries` in `verify.go`

Rename to `verifyNodeExhaustedRetries` and accept a `tableName string` parameter instead of hardcoding `"table_e"`. All call sites updated.

## 7. Delete `rerun_test.go`

The file and all helpers defined exclusively within it are deleted:
`callRerunEndpoint`, `waitForRerunDispatched`, `fixBrokenTableEAndReloadGraph`, `restoreBrokenTableE`, `waitForSchedulesReloaded`, `assertRerunTaskRetryCountZero`, `assertTaskStatus`, `assertInitStatusCompleted`, `assertTaskExecutionAtLeast`.

The rerun scenario will be revisited once a cancel endpoint exists.

## What stays unchanged

- `TestE2E_HappyPath_FullDAGExecution` and its helpers — no changes
- `schedule_catalog_test.go`, `trigger_test.go`, `ui_http_test.go` — no changes
- `clients.go`, `cleanup.go`, `helpers.go`, `trigger.go` — no changes beyond path updates from point 1
- The `dagNode` struct — kept in `failure_fixtures.go` (or moved to a shared file if both test files need it)
